Pass your raw API key in the `Authorization` header on every request (same convention as Mobula, zero migration friction).

```
Authorization: YOUR_API_KEY
```

Create and manage keys, watch usage and billing at [serialized.xyz/dashboard](https://serialized.xyz/dashboard).

## Try it instantly

Every endpoint page has an interactive playground that runs live against `https://demo.serialized.xyz`: no key needed, read endpoints, rate-limited per IP. Fill the parameters and send. To test with your own plan, switch the server to `https://api.serialized.xyz` and paste your key in the Authorization field.

## Plans

Each plan sets a monthly credit allowance (calendar month, UTC), a per-key rate limit and a per-second burst cap.

| Plan | Credits / month | Rate limit | Burst |
| --- | --- | --- | --- |
| Free | 15,000 | 60 req/min | 10 req/s |
| Starter | 150,000 | 1,200 req/min | 40 req/s |
| Growth | 2,000,000 | 2,400 req/min | 80 req/s |
| Enterprise | unlimited | 6,000 req/min | 150 req/s |

## Credits

Most endpoints cost **1 credit**. The heavier ones:

| Credits | Endpoints |
| --- | --- |
| 0 | `usage`, `meta/*`, `health` |
| 2 | `token/holders`, `token/top-traders`, `token/dev-tokens`, `wallet/positions`, `wallet/closed-positions`, `pool/top-traders` |
| 5 | `token/ohlcv`, `pool/ohlcv`, `search` |
| 10 | `token/security` |
| 750 | `audit/contract` |

POST batch endpoints bill **per item**. **Only successful (2xx) responses are billed**: you never pay for your own 4xx, for auth/quota/rate-limit rejections, or for a 5xx on our side.

Every billable response carries `X-Credits-Remaining` (the credits left in the current cycle; omitted on unlimited plans).

## Rate limits

The limit is per key, on a 1-minute window, with a per-second burst cap so a full minute's budget cannot land in a single second. Standard `X-RateLimit-*` headers are on every response; exceeding a limit returns `429` with code `RATE_LIMITED` and a `Retry-After` header.

A few endpoint groups carry their own per-key cap, identical on every plan:

| Group | Endpoints | Cap |
| --- | --- | --- |
| Wallet | `wallet/*` | 300 req/min |
| Traders | `token/top-traders`, `token/dev-tokens`, `pool/top-traders` | 150 req/min |
| Security | `token/security` | 100 req/min |
| Search | `search` | 200 req/min |
| Audit | `audit/contract` | 30 req/min |

## Quota exhaustion

When the monthly credit allowance is spent, billable endpoints return:

```json
{ "error": { "code": "QUOTA_EXCEEDED", "message": "Monthly credit quota exhausted — upgrade your plan or wait for the next cycle" } }
```

with HTTP `402` and `X-Credits-Remaining: 0`. Zero-credit endpoints (including `usage`) stay reachable so you can always inspect your own state and upgrade.

## Usage introspection

Query your own consumption programmatically — no credit cost, and a level of self-serve visibility no other provider exposes over the API:

- `GET /v1/usage` — current cycle: `{ keyId, tenant, plan, month, credits: { used, limit, remaining }, requests }`.
- `GET /v1/usage/history` — per-day series.
- `GET /v1/usage/breakdown` — per-endpoint.

A key only ever sees its own usage.

## WebSocket

The first frame authenticates with your key. Close codes:

| Code | Meaning |
| --- | --- |
| 4401 | Auth failure: key missing, invalid, or revoked (revoking a key also drops its open connections) |
| 4402 | Monthly credit quota exhausted (the WS mirror of the `402`) |
| 1008 | Policy: limits, floods, or a stuck socket |
| 1001 | Idle timeout |

Streaming usage is metered per minute.
