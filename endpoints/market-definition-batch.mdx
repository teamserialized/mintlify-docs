`POST /v1/pool` · **1 per market credit**

Batch twin: the static definition of up to 100 `{chain, address}` markets in one call, EVM and Solana mixed freely. The response comes back `200` in input order, one slot per market: `{ data }`, exactly the body of [`GET /v1/pool`](/endpoints/market-definition) for that market, or `{ error: { code, message } }` for that market alone (unknown pool, malformed address), never `null`. One bad market never costs you the rest of the lot. Billed per market.

Definitions are slow-changing, so a lot you poll comes back from cache after the first call; the single GET and the batch share it.

<Note>A slot's `data` is exactly what `GET /v1/pool` returns for that market: venue/type, launchpad or factory of origin, `feeBps`, base and quote token metadata, `priceNative`, `liquidityNative`, launchpad and bonding state, `createdAt`; see that page for the field rules.</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.serialized.xyz/v1/pool' \
  -H 'Authorization: YOUR_API_KEY' -H 'Content-Type: application/json' \
  -d '{"items":[{"chain":"evm:8453","address":"0x0ca6485b7e9cf814a3fd09d81672b07323535b64"},{"chain":"solana","address":"58oQChx4yWmvKdwLLZzBi4ChoCc2fqCUWBkwMihLYQo2"},{"chain":"evm:8453","address":"0x00000000000000000000000000000000deadbeef"}]}'
```
</RequestExample>
