`POST /v1/token/metadata` · **1 per item credit**

Batch twin: the metadata of up to 100 `{chain, address}` items in one call, EVM and Solana mixed freely. The response comes back `200` in input order, one slot per item: `{ data }`, exactly the body of [`GET /v1/token/metadata`](/endpoints/token-metadata) for that token, or `{ error: { code, message } }` for that item alone (unknown token, malformed address), never `null`. One bad item never costs you the rest of the lot. Billed per item.

<Note>A slot's `data` is exactly what `GET /v1/token/metadata` returns: `iconUrl` and `headerUrl` are always fetchable `https` URLs (`null` when no image is available), `dexPaid` is `true`, `false` or `null` (status unknown).</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.serialized.xyz/v1/token/metadata' \
  -H 'Authorization: YOUR_API_KEY' -H 'Content-Type: application/json' \
  -d '{"items":[{"chain":"evm:8453","address":"0x4ed4e862860bed51a9570b96d89af5e1b0efefed"},{"chain":"solana","address":"DezXAZ8z7PnrnRJjz3wXBoRgixCa6xjnB7YaB1pPB263"},{"chain":"solana","address":"11111111111111111111111111111112"}]}'
```
</RequestExample>
