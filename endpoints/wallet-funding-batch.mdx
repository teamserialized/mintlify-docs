`POST /v1/wallet/funding` · **1 per wallet credit**

Batch twin: the first funder of up to 100 `{chain, wallet}` items in one call, EVM and Solana mixed freely, with at most 20 Solana wallets per call. Every item names its `chain` (the first funder is read per chain). The response comes back `200` in input order, one slot per wallet: `{ data }`, exactly the body of [`GET /v1/wallet/funding`](/endpoints/wallet-funding) for that wallet (`data: null` when no funder is known, as on the GET), or `{ error: { code, message } }` for that wallet alone (unknown chain, malformed address), never a missing slot. One bad wallet never costs you the rest of the lot. Billed per wallet.

<Note>A slot's `data` is exactly what `GET /v1/wallet/funding` returns for that wallet: `funder`, `fundedAt`, `txHash`, `amountNative` and `funderTag`; see that page for the fields. A call with more than 20 Solana wallets is refused as a whole (`400`).</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.serialized.xyz/v1/wallet/funding' \
  -H 'Authorization: YOUR_API_KEY' -H 'Content-Type: application/json' \
  -d '{"items":[{"chain":"evm:8453","wallet":"0xd13da05b9288ba4961973110594bd0fe3428791f"},{"chain":"solana","wallet":"GuhieZDx6nwJV14WjeUQH2ted6CGPKoGCCTaPSPNgG2E"},{"chain":"evm:8453","wallet":"0x95d955179a7cd45aeef394ed39f6a8d8b1bd1e09"}]}'
```
</RequestExample>
