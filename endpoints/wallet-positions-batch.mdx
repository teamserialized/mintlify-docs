`POST /v1/wallet/positions` · **2 per wallet credits**

Batch twin: up to 20 wallets per call, response array in input order. Each slot is `{ data, summary, hasMore }`, the body of the single GET for that wallet, or `{ error }` when that wallet failed, so one wallet never fails the others. `minValueUsd`, `includeNative`, `includeStables`, `limit` and `offset` apply to every wallet of the call. Billed per wallet.

<Note>Each `items[]` entry takes a `wallet` and an optional `chain` (omit it for all EVM chains of a hex address; a base58 address is Solana). A slot's `data`, `summary` and `hasMore` are exactly what `GET /v1/wallet/positions` returns for that wallet with the same options; see that page for the row fields.</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.serialized.xyz/v1/wallet/positions' \\
  -H 'Authorization: YOUR_API_KEY' -H 'Content-Type: application/json' \\
  -d '{"items":[{"wallet":"Hasda78TSaT9bjiPxDBvP4GpohFpP3TDTaJEcCYK5kyN","chain":"solana"},{"wallet":"0x95d955179a7cd45aeef394ed39f6a8d8b1bd1e09","chain":"evm:8453"}],"limit":1}'
```
</RequestExample>
