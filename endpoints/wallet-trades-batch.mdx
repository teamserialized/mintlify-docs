`POST /v1/wallet/trades` · **1 per wallet credits**

Batch twin: up to 20 wallets per call, response array in input order. Each slot is `{ data, hasMore, nextCursor, oldestAt, usdBasis }`, the body of the single GET for that wallet, or `{ error }` when that wallet failed, so one wallet never fails the others. Every item names its `chain` (the trade tape is per chain) and may carry its own `cursor`: each wallet paginates independently with the `nextCursor` of its slot. `limit`, `beforeAt`, `fromAt` and `includeRoutingHops` apply to every wallet of the call. Billed per wallet.

<Note>A slot's `data`, `hasMore`, `nextCursor`, `oldestAt` and `usdBasis` are exactly what `GET /v1/wallet/trades` returns for that wallet with the same options; see that page for the row fields and the pagination contract (`hasMore: false` means the wallet's history is fully served).</Note>

<RequestExample>
```bash cURL
curl -X POST 'https://api.serialized.xyz/v1/wallet/trades' \\
  -H 'Authorization: YOUR_API_KEY' -H 'Content-Type: application/json' \\
  -d '{"items":[{"wallet":"0xd13da05b9288ba4961973110594bd0fe3428791f","chain":"evm:8453"},{"wallet":"GuhieZDx6nwJV14WjeUQH2ted6CGPKoGCCTaPSPNgG2E","chain":"solana"}],"limit":1}'
```
</RequestExample>
