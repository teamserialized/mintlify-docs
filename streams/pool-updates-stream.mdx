`WS channel: pool-updates`

Live refresh of a single market's mutable fields - price, market cap, liquidity, bonding progress, windowed stats. The price moves instantly on every trade of the pool; the full snapshot refreshes server-side every ~10s. Events are throttled to at most one per second per pool and deduplicated - you only receive an event when something actually changed.

<ParamField body="chain" type="string" required>
  Public chain id - `evm:<id>` or `solana`. Example: `solana`
</ParamField>

<ParamField body="pool" type="string" required>
  Pool (market) address. Example: `BqnpCdDLPV2pFdAaLnVidmn3G93RP2p5oRdGEY2sJGez`
</ParamField>

<Note>The refresh runs server-side through the same engine as [`/v1/pool/data`](/endpoints/market-data), so `stats` carries the identical `5m`/`1h`/`24h` windows and field names as the REST snapshot - re-parse events with the code you already wrote. On subscribe, the last known state is pushed immediately when available.</Note>

## Close codes

| Code | Meaning |
|---|---|
| `4401` | Auth - key missing, invalid, or revoked. Live connections are dropped the moment a key is revoked. |
| `4402` | Monthly credit quota exhausted (the WebSocket mirror of REST `402`). |
| `1008` | Policy - subscription limits, flooding, or a blocked socket. |
| `1001` | Idle timeout - no `ping` within the keepalive window. |

<RequestExample>
```json Subscribe
{
  "op": "subscribe",
  "channel": "pool-updates",
  "id": "pool-1",
  "params": {
    "chain": "solana",
    "pool": "BqnpCdDLPV2pFdAaLnVidmn3G93RP2p5oRdGEY2sJGez"
  }
}
```
</RequestExample>
